## 0. 一句话总览

Lab2 的物理内存管理可以压缩成一条链：

```
entry.S（先开页表）
  → kern_init()
    → dtb_init()              拿到内存起点和大小
    → pmm_init()
      → init_pmm_manager()    注册并初始化分配器
      → page_init()           建立 Page 描述符数组、划出空闲区
        → init_memmap()       把空闲区交给分配器
          → best_fit_init_memmap()
      → check_alloc_page()    自测分配/释放
  → 之后运行时：
      alloc_pages()  → best_fit_alloc_pages()
      free_pages()   → best_fit_free_pages()
```

指导书对这一主线的概括是：

```
pmm_init() -> init_pmm_manager() -> page_init() -> init_memmap()
          -> alloc_pages() / free_pages()
```

其中 **`entry.S` 在进入 `kern_init()` 之前就已经建立启动页表并开启 Sv39 分页**，所以后面所有 C 代码都运行在虚拟地址空间中；`page_init()` 是在「分页已经开启」的前提下，建立 Page 描述符和初始空闲页区间。

## 1. 总体调用图

```

  ├─ satp ← (8 << 60) | 页表物理页号
  ├─ sfence.vma              刷新 TLB
  ├─ sp ← bootstacktop       切到内核自己的栈
  └─ jr kern_init            跳到高虚拟地址运行
        │
        ▼
kern_init  (kern/init/init.c:28)
  ├─ memset(edata, 0, end - edata)     清 BSS
  ├─ dtb_init()                        解析设备树
  │    └─ extract_memory_info()
  ├─ cons_init()                       初始化控制台
  ├─ cputs(...) / print_kerninfo()
  └─ pmm_init()                        (kern/mm/pmm.c:121)
       ├─ init_pmm_manager()           (pmm.c:36)
       │    ├─ pmm_manager = &best_fit_pmm_manager
       │    └─ best_fit_init()         空链表、nr_free = 0
       ├─ page_init()                  (pmm.c:72)
       │    ├─ get_memory_base() / get_memory_size()
       │    ├─ va_pa_offset = PHYSICAL_MEMORY_OFFSET
       │    ├─ npage = PPN(mem_end)
       │    ├─ pages = ROUNDUP(end, 4KiB)
       │    ├─ 对 [nbase, npage) 全部 SetPageReserved
       │    ├─ freemem = ROUNDUP(pages + 描述符数组大小, 4KiB)
       │    └─ init_memmap(pa2page(freemem_pa), npage - free_start)
       │         └─ best_fit_init_memmap()

       │    └─ best_fit_check()
       └─ 输出 satp_virtual / satp_physical
```

运行时再通过 `pmm_manager` 的函数指针分发：

```
alloc_pages(n) ──► pmm_manager->alloc_pages ──► best_fit_alloc_pages()
free_pages(p,n) ─► pmm_manager->free_pages  ──► best_fit_free_pages()

```

## 2. 阶段 0：从 OpenSBI 到 `kern_entry`

### 2.1 开机时的状态

QEMU 的 RISC-V virt 机器默认 DRAM 范围是：

```
[0x80000000, 0x88000000)    共 128 MiB
```

其中：

```
[0x80000000, 0x80200000)    OpenSBI 占用（2 MiB）
[0x80200000, KernelEnd)     内核镜像
```

OpenSBI 把内核加载到 `0x80200000`，并在跳转前准备好：

| 寄存器 | 内容 |
|---|---|
| `a0` | hartid，当前 CPU 核编号 |
| `a1` | DTB（设备树）的**物理地址** |

此时 CPU 处于 S Mode，`satp` 的 MODE 为 Bare，也就是**还没开分页**，所有地址都按物理地址处理。

### 2.2 `kern_entry` 为什么要先建页表

链接脚本 [tools/kernel.ld](../code/tools/kernel.ld) 把内核起始地址改成了：

```c
BASE_ADDRESS = 0xFFFFFFFFC0200000;
```

因此编译器和链接器认为内核运行在 `0xffffffffc0200000` 之后的高虚拟地址。可是 CPU 现在还没开分页，直接跳 `kern_init` 会跳到一个巨大的物理地址，必然出错。

所以 `kern_entry` 先做三件事：

1. **保存参数**：`a0`、`a1` 分别存入 `boot_hartid`、`boot_dtb`；
2. **建立启动页表**：`boot_page_table_sv39` 只有一个有效页表项，把
   `[0xffffffffc0000000, 0xffffffffffffffff]` 这 1 GiB 虚拟空间映射到
   `[0x80000000, 0xc0000000)` 物理空间；
3. **开启分页**：设置 `satp`，执行 `sfence.vma` 刷新 TLB，然后设置栈指针并跳转 `kern_init`。

页表项的核心写法是：

```asm
.quad (0x80000 << 10) | 0xcf    # PPN = 0x80000，V/R/W/X/A/D 全为 1
```

- `0x80000` 是物理基址 `0x80000000 >> 12`；
- `0xcf = 1100_1111b`，对应 `V=1, R=1, W=1, X=1, A=1, D=1`；
- 这是一个 **1 GiB 大页（gigapage）**，不是三级页表逐级映射。

设置的 `satp` 为：

```
satp = (8 << 60) | 页表物理页号
       └──────┘
       MODE=8，表示 Sv39
```

### 2.3 本阶段的关键点

- **页表先于物理内存管理**：`page_init()` 运行时，分页已经开启；
- 内核代码、全局变量、`end` 符号都是**高虚拟地址**；
- 物理内存管理器看到的物理页号仍然是 `0x80000` 起步；
- 因此后面必须频繁使用 `PADDR`、`PPN`、`page2pa`、`pa2page` 在几种地址表示之间转换。

## 3. 阶段 1：`kern_init()` 前半段

对应代码：[kern/init/init.c:28](../code/kern/init/init.c#L28)

```c
int kern_init(void) {
    extern char edata[], end[];
    memset(edata, 0, end - edata);
    dtb_init();
    cons_init();
    const char *message = "(THU.CST) os is loading ...\0";
    cputs(message);
    print_kerninfo();
    pmm_init();
    while (1) ;
}
```

### 3.1 `memset(edata, 0, end - edata)`：清 BSS

- `edata` 到 `end` 之间是内核的 BSS 段；
- `pages`、`npage`、`va_pa_offset`、`pmm_manager`、`memory_base`、`memory_size` 等全局变量都在这里；
- **必须先清零，再调用 `dtb_init()`**，否则 `dtb_init()` 刚写进 `memory_base/memory_size` 的值会被清掉。

这是初始化顺序上的第一个坑。

### 3.2 `dtb_init()`：从设备树读物理内存范围

对应代码：[kern/driver/dtb.c:107](../code/kern/driver/dtb.c#L107)

调用关系：

```
dtb_init()
  └─ extract_memory_info()
       ├─ fdt32_to_cpu() / fdt64_to_cpu()
       └─ 遍历 FDT token，找到 memory 节点的 reg 属性
```

它做的事：

1. 打印 hartid 和 DTB 物理地址；
2. 把 `boot_dtb`（物理地址）加上 `PHYSICAL_MEMORY_OFFSET`，转成内核虚拟地址；
3. 检查 DTB 头部魔数是否为 `0xd00dfeed`；
4. 遍历设备树结构，找到名字以 `memory` 开头的节点；
5. 读取该节点的 `reg` 属性（16 字节：`base` + `size`，都是大端 64 位）；
6. 保存到静态全局变量：

```c
static uint64_t memory_base = 0;
static uint64_t memory_size = 0;
```

7. 对外提供：

```c
uint64_t get_memory_base(void);
uint64_t get_memory_size(void);
```

在 QEMU 默认配置下得到：

```
memory_base = 0x80000000
memory_size = 0x08000000      // 128 MiB
mem_end     = 0x88000000
```

> 注意：`dtb_init()` 只读取 DTB 中的信息，并不把 DTB 占用的那块内存标记为保留。当前实现默认之后可以复用这块空间。
>
> 另外，这一步只是**知道内存在哪、有多大**，还没有建立任何页描述符或空闲链表。

### 3.3 `cons_init()`、`cputs()`、`print_kerninfo()`

这三个函数与物理内存分配没有直接关系，但属于启动链的一部分：

| 函数 | 作用 |
|---|---|
| `cons_init()` | 初始化串口控制台，之后 `cprintf` 才能输出 |
| `cputs()` | 输出 `(THU.CST) os is loading ...` |
| `print_kerninfo()` | 打印 `etext`、`edata`、`end` 等内核符号和内核镜像大小 |

`print_kerninfo()` 的输出能帮助我们确认 `end` 在哪里，而 `end` 正是 Page 描述符数组的起点依据。

## 4. 阶段 2：`pmm_init()` 物理内存管理初始化

对应代码：[kern/mm/pmm.c:121](../code/kern/mm/pmm.c#L121)

```c
void pmm_init(void) {
    init_pmm_manager();   // 1. 选择并初始化分配器
    page_init();          // 2. 探测内存、建立描述符、划出空闲区
    check_alloc_page();   // 3. 自测
    // 4. 输出启动页表的虚拟地址和物理地址
}
```

### 4.1 `init_pmm_manager()`：先注册分配器

对应代码：[kern/mm/pmm.c:36](../code/kern/mm/pmm.c#L36)

```c
static void init_pmm_manager(void) {
    pmm_manager = &best_fit_pmm_manager;
    cprintf("memory management: %s\n", pmm_manager->name);
    pmm_manager->init();
}
```

#### 为什么要有 `pmm_manager`

ucore 用「结构体 + 函数指针」实现了一个简单的面向对象式接口：

```c
struct pmm_manager {
    const char *name;
    void (*init)(void);
    void (*init_memmap)(struct Page *base, size_t n);
    struct Page *(*alloc_pages)(size_t n);
    void (*free_pages)(struct Page *base, size_t n);
    size_t (*nr_free_pages)(void);
    void (*check)(void);
};
```

不同的分配算法只需要实现同一组接口，然后替换 `pmm_manager` 指针即可：

- First-Fit → `default_pmm_manager`
- Best-Fit → `best_fit_pmm_manager`
- Buddy → `buddy_pmm_manager`

本实验最终接入的是 **Best-Fit**。

#### `best_fit_init()` 做什么

对应代码：[kern/mm/best_fit_pmm.c:26](../code/kern/mm/best_fit_pmm.c#L26)

```c
static void best_fit_init(void) {
    list_init(&free_list);
    nr_free = 0;
}
```

只做两件事：

1. 初始化空闲块双向链表的头节点；
2. 空闲页计数清零。

此时还**没有任何空闲页**，因为 `page_init()` 还没运行。

#### 为什么必须先调用它

`page_init()` 最后会通过：

```c
static void init_memmap(struct Page *base, size_t n) {
    pmm_manager->init_memmap(base, n);
}
```

调用当前管理器的 `init_memmap`。如果 `pmm_manager` 还没赋值，这里就是空指针；如果 `best_fit_init()` 没跑，链表头就没有初始化。所以顺序必须是：

```
init_pmm_manager()  →  page_init()
```

### 4.2 `page_init()`：本实验最核心的函数

对应代码：[kern/mm/pmm.c:72](../code/kern/mm/pmm.c#L72)

它的目标可以概括为一句话：

> **根据 DTB 给出的物理内存范围，在内核镜像之后建立 `struct Page` 描述符数组，并把描述符数组之后、内存末端之前的完整物理页交给物理内存管理器。**

#### 4.2.1 先分清四种「地址/编号」

| 概念 | 含义 | 例子 |
|---|---|---|
| 虚拟地址 VA | 内核链接、运行使用的地址 | `end = 0xffffffffc0205058` |
| 物理地址 PA | 内存总线上的真实地址 | `PADDR(end) = 0x80205058` |
| 物理页号 PPN | `PA >> 12`，一页 4 KiB | `PPN(0x80200000) = 0x80200` |
| Page 描述符地址 | `struct Page` 数组中的某个元素 | `pages[i]` |

常用转换：

```c
PADDR(kva)              // 内核虚拟地址 → 物理地址：kva - va_pa_offset
PPN(pa)                 // 物理地址 → 物理页号：pa >> 12
page2ppn(page)          // Page 指针 → 物理页号：page - pages + nbase
page2pa(page)           // Page 指针 → 物理地址：page2ppn(page) << 12
pa2page(pa)             // 物理地址 → Page 指针：&pages[PPN(pa) - nbase]
```

#### 4.2.2 逐步拆解 `page_init()`

```c
static void page_init(void) {
    // ① 从设备树获取物理内存起点与大小
    uint64_t mem_begin = get_memory_base();
    uint64_t mem_size  = get_memory_size();

    if (mem_begin == 0 || mem_size == 0) {
        panic("page_init: invalid physical memory info from DTB");
    }
    uint64_t mem_end = mem_begin + mem_size;

    // ② 建立虚拟地址到物理地址的换算偏移
    va_pa_offset = PHYSICAL_MEMORY_OFFSET;

    // ③ 计算可管理物理页号上界
    npage = PPN(mem_end);
    if (npage <= nbase) {
        panic("page_init: no usable physical memory");
    }

    // ④ Page 描述符数组放在内核 end 之后，并按页对齐
    extern char end[];
    pages = (struct Page *)ROUNDUP((uintptr_t)end, PGSIZE);

    // ⑤ 先把 [nbase, npage) 的所有页标记为保留
    for (size_t i = 0; i < npage - nbase; i++) {
        SetPageReserved(pages + i);
    }

    // ⑥ 描述符数组之后的第一个可分配页
    uintptr_t freemem = ROUNDUP((uintptr_t)pages +
                                (npage - nbase) * sizeof(struct Page), PGSIZE);
    uintptr_t freemem_pa = PADDR(freemem);

    // ⑦ 输出探测结果
    cprintf("physical memory map:\n");
    cprintf("memory: 0x%016lx, [0x%016lx, 0x%016lx].\n",
            mem_size, mem_begin, mem_end - 1);

    // ⑧ 只把描述符数组之后、内存末端之前的完整页交给分配器
    size_t free_start = PPN(freemem_pa);
    if (free_start < npage) {
        init_memmap(pa2page(freemem_pa), npage - free_start);
    }
}
```

#### ① 读取 DTB 信息

```c
uint64_t mem_begin = get_memory_base();   // 0x80000000
uint64_t mem_size  = get_memory_size();   // 0x08000000
uint64_t mem_end   = mem_begin + mem_size;// 0x88000000
```

如果 DTB 解析失败，这两个值是 0，直接 `panic`，避免后面用错误范围建立描述符。

#### ② 设置 `va_pa_offset`

```c
va_pa_offset = PHYSICAL_MEMORY_OFFSET;    // 0xFFFFFFFF40000000
```

`PADDR` 的定义是：

```c
#define PADDR(kva) (kva - va_pa_offset)
```

所以**任何 `PADDR` 调用之前都必须先设置它**。这是报告里特别提到的第一个 bug：如果先调用 `PADDR(freemem)`、后设置 `va_pa_offset`，偏移量还是 0，算出来的物理地址就是错的。

举例：

```
KERNBASE              = 0xFFFFFFFFC0200000
PHYSICAL_MEMORY_OFFSET= 0xFFFFFFFF40000000
PADDR(KERNBASE)       = 0x0000000080200000
```

#### ③ 计算 `npage`

```c
npage = PPN(mem_end);   // PPN(0x88000000) = 0x88000
```

- `nbase = DRAM_BASE / PGSIZE = 0x80000000 >> 12 = 0x80000`
- `npage = 0x88000`
- 物理内存总页数：`npage - nbase = 0x8000 = 32768` 页

`npage` 是**内核可管理的物理页号上界**，不是「页数」。描述符数组需要覆盖 `[nbase, npage)` 的每一个物理页，包括 OpenSBI 和内核镜像占用的页。

#### ④ 确定 `pages` 数组的位置

```c
extern char end[];
pages = (struct Page *)ROUNDUP((uintptr_t)end, PGSIZE);
```

- `end` 是链接脚本定义的**内核镜像结尾虚拟地址**；
- 描述符数组紧跟在 `end` 后面；
- 按 4 KiB 向上对齐，保证数组从页边界开始；
- `pages` 保存的是数组的**虚拟地址**，之后用 `pages[i]` 访问。

为什么描述符数组不放在别处？因为此时还没有堆分配器，内核能确定「不会被别人用」的区域就是 `end` 之后。

#### ⑤ 先把所有页标记为保留

```c
for (size_t i = 0; i < npage - nbase; i++) {
    SetPageReserved(pages + i);
}
```

这一步把 `[nbase, npage)` 对应的**所有** Page 描述符都置为 `PG_reserved`：

- OpenSBI 占用的页；
- 内核镜像占用的页；
- 描述符数组自身占用的页；
- 以及后面真正空闲的页。

先全部保留，是为了防止「布局还没算完，就有页被分配出去」。之后 `init_memmap()` 只会对真正的空闲区清除保留位。

`PG_reserved` 和 `PG_property` 的区别：

| 标志 | 含义 |
|---|---|
| `PG_reserved` | 该页被保留，不能分配/释放 |
| `PG_property` | 该 Page 是某个**空闲块的头页**，`property` 记录块大小 |

一个页可以既不是 reserved，也不是 property head：它可能是一个已分配块中的普通页。

#### ⑥ 计算第一个可分配页 `freemem`

```c
uintptr_t freemem = ROUNDUP((uintptr_t)pages +
                            (npage - nbase) * sizeof(struct Page), PGSIZE);
```

拆开看：

- `pages`：描述符数组起始虚拟地址；
- `(npage - nbase)`：描述符个数，`32768`；
- `sizeof(struct Page)`：当前平台上是 **40 字节**
  （`int ref` 4 + 对齐 4 + `uint64_t flags` 8 + `unsigned int property` 4 + 对齐 4 + `list_entry_t page_link` 16）；
- 数组总大小：`32768 × 40 = 1,310,720 字节 = 0x140000`；
- 再按 4 KiB 向上对齐，得到第一个可分配页的虚拟地址；
- 用 `PADDR(freemem)` 转成物理地址，因为后面要算 PPN。

以报告中一次运行的实际数值为例：

```
end          = 0xffffffffc0205058   （虚拟地址，随代码大小变化）
pages        = 0xffffffffc0206000   （ROUNDUP(end, 4KiB)，虚拟地址）
pages 物理地址= 0x0000000080206000
描述符数组大小= 0x140000
freemem      = 0xffffffffc0206000 + 0x140000
             = 0xffffffffc0346000   （虚拟地址）
freemem_pa   = 0x0000000080346000   （物理地址）
free_start   = PPN(0x80346000) = 0x80346
```

空闲页数：

```
npage - free_start = 0x88000 - 0x80346
                   = 0x7CBA
                   = 31930 页
```

约 `31930 × 4 KiB ≈ 124.7 MiB`。这与报告中 Buddy 自测输出 `arena ... 31930 pages` 完全一致。

> 注：报告正文的示例表曾把 `end` 写成 `0xffffffffc0206078`，那是较早一次构建的数值；最终运行输出为 `0xffffffffc0205058`。重新编译后 `end`、`pages`、`freemem` 都会随内核大小变化，但计算流程和「空闲页数 = `npage - free_start`」的关系不变。


#### ⑧ 调用 `init_memmap()` 建立空闲区

```c
size_t free_start = PPN(freemem_pa);
if (free_start < npage) {
    init_memmap(pa2page(freemem_pa), npage - free_start);
}
```

- `pa2page(freemem_pa)`：把物理地址转成对应的 Page 描述符指针，作为空闲块的头页；
- `npage - free_start`：空闲页数；
- 如果 `free_start >= npage`，说明没有完整的一页可用，就**不调用** `init_memmap()`，避免传入 0 页。

`init_memmap()` 是一个薄封装：

```c
static void init_memmap(struct Page *base, size_t n) {
    pmm_manager->init_memmap(base, n);
}
```

当前 `pmm_manager` 是 Best-Fit，所以实际进入：

```c
best_fit_init_memmap(base, n);
```

```
物理地址低端                                              物理地址高端
0x80000000                                              0x88000000
   │                                                        │
   ├──────── OpenSBI ────────┤                              │
   │        2 MiB            │                              │
```

对应的虚拟地址区间则是整体加上 `0xFFFFFFFF40000000`：

```

```

> 注意最后一行的虚拟地址写法只是示意「物理地址 + 偏移」，实际 `0x88000000 + 0xFFFFFFFF40000000 = 0xFFFFFFFFC8000000`，仍在启动页表映射的 1 GiB 范围内。

#### 4.2.4 `page_init()` 的四个关键点

1. **描述符数量是 `npage - nbase`，不是 `npage`**
   描述符只覆盖 DRAM 范围 `[0x80000000, 0x88000000)`，不是从物理地址 0 开始。

2. **描述符数组本身不能被分配**
   它位于 `pages` 到 `freemem` 之间，必须先标记 reserved，且 `freemem` 要从数组末尾之后算起。

3. **起点向上对齐，末端向下取整**
   - `pages`、`freemem` 用 `ROUNDUP`；
   - `npage = PPN(mem_end)` 天然把末尾不足一页的部分丢掉。
   只有 `[free_start, npage)` 之间的**完整页**才进入空闲区。

4. **先全部 reserved，再由 `init_memmap` 清除**
   `best_fit_init_memmap()` 会遍历空闲区：

   ```c
   for (; p != base + n; p++) {
       assert(PageReserved(p));
       p->flags = p->property = 0;   // 清除 reserved 和 property
       set_page_ref(p, 0);
   }
   ```

   这样 OpenSBI、内核、描述符数组所在的页仍然是 reserved，而真正的空闲页变成可用。

### 4.3 `best_fit_init_memmap()`：把空闲区登记成空闲块

对应代码：[kern/mm/best_fit_pmm.c:33](../code/kern/mm/best_fit_pmm.c#L33)

```c
static void best_fit_init_memmap(struct Page *base, size_t n) {
    assert(n > 0);
    struct Page *p = base;
    for (; p != base + n; p++) {
        assert(PageReserved(p));
        p->flags = p->property = 0;
        set_page_ref(p, 0);
    }
    base->property = n;
    SetPageProperty(base);
    nr_free += n;

    // 按地址升序插入 free_list
    ...
}
```

它完成：

1. 检查 `[base, base+n)` 的每一页确实处于 reserved 状态；
2. 清除每页的 `flags` 和 `property`，引用计数置 0；
3. 把**首 Page** `base` 的 `property` 设为 `n`，表示这是一个 `n` 页的连续空闲块；
4. 给 `base` 打上 `PG_property`，表示它是空闲块头；
5. `nr_free += n`；
6. 把 `base->page_link` 按地址升序插入 `free_list`。

初始化完成后，空闲链表里只有**一个节点**：

```
free_list ──► [base, property = 31930] ──► free_list
nr_free = 31930
```

这时物理内存管理器已经可以开始分配了。

### 4.4 `check_alloc_page()`：自测分配与释放

对应代码：[kern/mm/pmm.c:142](../code/kern/mm/pmm.c#L142)


Best-Fit 的 `check` 是 `best_fit_check()`：

- 先做 `basic_check()`：
  - 分配 3 个单页，检查非空、互不相同；

  - 用 `assert(p0 + 4 == p1)` 验证。

## 5. 阶段 3：运行时的分配与释放

初始化完成后，内核其他模块通过 `pmm.c` 提供的三个包装函数使用物理内存：

```c
struct Page *alloc_pages(size_t n);
void free_pages(struct Page *base, size_t n);
size_t nr_free_pages(void);
```

它们都只是转发到 `pmm_manager` 的函数指针。

### 5.1 `alloc_pages(n)` → `best_fit_alloc_pages(n)`

对应代码：[kern/mm/best_fit_pmm.c:63](../code/kern/mm/best_fit_pmm.c#L63)

```c
static struct Page *best_fit_alloc_pages(size_t n) {
    assert(n > 0);
    if (n > nr_free) {
        return NULL;
    }

    struct Page *page = NULL;
    list_entry_t *le = &free_list;

    // 1. 遍历整个空闲链表，找 property >= n 且 property 最小的块
    while ((le = list_next(le)) != &free_list) {
        struct Page *p = le2page(le, page_link);
        if (p->property >= n &&
            (page == NULL || p->property < page->property)) {
            page = p;
        }
    }

    if (page != NULL) {
        // 2. 从链表摘下
        list_entry_t *prev = list_prev(&(page->page_link));
        list_del(&(page->page_link));

        // 3. 如果块比请求大，分裂：后半部分作为新空闲块
        if (page->property > n) {
            struct Page *p = page + n;
            p->property = page->property - n;
            SetPageProperty(p);
            list_add(prev, &(p->page_link));  // 插回原位置，保持地址有序
        }

        // 4. 更新计数和标志
        nr_free -= n;
        ClearPageProperty(page);
    }
    return page;
}
```

流程：

1. **快速失败**：请求页数超过总空闲页数，直接返回 `NULL`；
2. **最佳匹配**：遍历整个链表，记录 `property >= n` 中 `property` 最小的块；
3. **摘链**：把选中的块从 `free_list` 删除；
4. **分裂**：
   - 如果块刚好 `n` 页，全部返回；
   - 如果块大于 `n` 页，从 `page + n` 处切开，后半部分作为新的空闲块；
   - 新块插回原位置，保持链表按地址升序；
5. **记账**：`nr_free -= n`；
6. **清标志**：清除返回块头页的 `PG_property`，表示它不再是空闲块头；
7. 返回 `page`，调用者用 `page2pa(page)` 得到物理地址，或用 `page2kva` 得到虚拟地址。

举例：空闲链表只有一个 31930 页的块，请求 5 页：

```
分配前： [base, property=31930]
分配后： [base+5, property=31925]
返回：   base（5 页）
nr_free: 31930 → 31925
```

### 5.2 `free_pages(base, n)` → `best_fit_free_pages(base, n)`

对应代码：[kern/mm/best_fit_pmm.c:96](../code/kern/mm/best_fit_pmm.c#L96)

```c
static void best_fit_free_pages(struct Page *base, size_t n) {
    assert(n > 0);

    // 1. 清理每一页的状态
    struct Page *p = base;
    for (; p != base + n; p++) {
        assert(!PageReserved(p) && !PageProperty(p));
        p->flags = 0;
        set_page_ref(p, 0);
    }

    // 2. 把释放区登记成一个新的空闲块
    base->property = n;
    SetPageProperty(base);
    nr_free += n;

    // 3. 按地址升序插入 free_list
    ...

    // 4. 与前一个空闲块合并
    list_entry_t *le = list_prev(&(base->page_link));
    if (le != &free_list) {
        p = le2page(le, page_link);
        if (p + p->property == base) {
            p->property += base->property;
            ClearPageProperty(base);
            list_del(&(base->page_link));
            base = p;
        }
    }

    // 5. 与后一个空闲块合并
    le = list_next(&(base->page_link));
    if (le != &free_list) {
        p = le2page(le, page_link);
        if (base + base->property == p) {
            base->property += p->property;
            ClearPageProperty(p);
            list_del(&(p->page_link));
        }
    }
}
```

流程：

1. **检查并清理**：确保每一页都不是 reserved、也不是空闲块头；清 `flags`、引用计数；
2. **建立新空闲块**：`base->property = n`，打 `PG_property`；
3. **按地址插入**：空闲链表必须保持按 Page 地址升序，否则无法正确判断相邻关系；
4. **向前合并**：如果前一个块 `p` 满足 `p + p->property == base`，把当前块并入前一个块；
5. **向后合并**：如果后一个块 `p` 满足 `base + base->property == p`，把后一个块并入当前块；
6. `nr_free` 在步骤 2 已经加过，合并只改 `property`，不重复加。

合并的意义：避免释放后产生大量相邻的小空闲块，减少外部碎片。

### 5.3 `nr_free_pages()` → `best_fit_nr_free_pages()`

```c
static size_t best_fit_nr_free_pages(void) {
    return nr_free;
}
```

直接返回当前空闲页总数。测试函数用它检查分配/释放前后是否守恒。

### 5.4 First-Fit 与 Best-Fit 的唯一区别

两者初始化、释放、合并、计数完全相同，**只有分配时的选择策略不同**：

| 算法 | 选择哪个空闲块 | 代码特征 |
|---|---|---|
| First-Fit | 链表从头开始，第一个 `property >= n` 的块 | 找到就 `break` |
| Best-Fit | 遍历全表，`property >= n` 且 `property` 最小的块 | 不 `break`，持续比较 |

First-Fit 参考实现见 [kern/mm/default_pmm.c](../code/kern/mm/default_pmm.c)；Best-Fit 见 [kern/mm/best_fit_pmm.c](../code/kern/mm/best_fit_pmm.c)。

Best-Fit 的优点是残留碎片更小；缺点是必须遍历整个链表，且可能把大块切出很小的剩余块，长期运行后反而产生更细碎的外部碎片。

## 6. 数据结构与地址转换速查

### 6.1 `struct Page`

定义在 [kern/mm/memlayout.h](../code/kern/mm/memlayout.h)：

```c
struct Page {
    int ref;                  // 引用计数
    uint64_t flags;           // PG_reserved / PG_property
    unsigned int property;    // 空闲块大小（页数），仅块头有效
    list_entry_t page_link;   // 空闲链表节点
};
```

一个 `struct Page` 描述**一个 4 KiB 物理页**，所有描述符连续排成数组。

### 6.2 `free_area_t`

```c
typedef struct {
    list_entry_t free_list;   // 空闲块链表头
    unsigned int nr_free;     // 空闲页总数
} free_area_t;
```

- `free_list` 的每个节点是一个空闲块的**头页**；
- `property` 记录该块包含多少页；
- 链表按 Page 地址升序排列，方便合并。

### 6.3 地址转换公式

| 转换 | 公式 | 说明 |
|---|---|---|
| VA → PA | `PADDR(va) = va - va_pa_offset` | 仅内核虚拟地址 |
| PA → VA | `pa + va_pa_offset` | 当前代码中 `KADDR` 被注释，SLUB 里用 `page2pa + va_pa_offset` |
| PA → PPN | `PPN(pa) = pa >> 12` | 4 KiB 页 |
| Page → PPN | `page - pages + nbase` | 数组下标加基页号 |
| Page → PA | `(page - pages + nbase) << 12` | `page2pa` |
| PA → Page | `&pages[PPN(pa) - nbase]` | `pa2page` |

### 6.4 关键全局变量

| 变量 | 含义 |
|---|---|
| `pages` | Page 描述符数组的虚拟地址 |
| `npage` | 可管理物理页号上界（`PPN(mem_end)`） |
| `nbase` | DRAM 起始页号（`0x80000`） |
| `va_pa_offset` | 虚拟地址与物理地址的固定偏移（`0xFFFFFFFF40000000`） |
| `pmm_manager` | 当前物理内存管理器 |
| `free_area` | 当前管理器的空闲链表和计数 |

## 8. 初学者最容易混淆/出错的点

1. **`end` 是虚拟地址，不是物理地址**
   `pages = ROUNDUP(end, PGSIZE)` 得到的是虚拟地址；计算空闲区物理起点必须再 `PADDR(freemem)`。

2. **`va_pa_offset` 必须最先赋值**
   任何 `PADDR` 调用之前都要设置好，否则偏移为 0，物理地址全错。

3. **描述符个数是 `npage - nbase`**
   不是 `npage`，也不是 `npage * sizeof(struct Page)` 直接当页数。

4. **`npage` 是页号上界，不是页数**
   页数是 `npage - nbase`，空闲页数是 `npage - free_start`。

5. **`PageProperty` 表示「空闲块头」，不是「这一页空闲」**
   已分配块中的普通页既不是 reserved，也没有 property。

6. **空闲链表必须按地址升序**
   `free_pages` 的合并逻辑依赖前后相邻关系；插入位置错了，合并就会失效。

7. **`init_memmap` 只能传完整页**
   `npage = PPN(mem_end)` 已经丢掉末尾不足一页的部分；`freemem` 也要向上对齐。

8. **初始化顺序不能乱**
   ```
   memset → dtb_init → pmm_init
                 └─ init_pmm_manager → page_init → init_memmap
   ```
   `page_init` 依赖 DTB 信息、`va_pa_offset`、已注册的 `pmm_manager`；`satp_physical = PADDR(...)` 依赖 `va_pa_offset`。

9. **启动页表在 `pmm_init` 之前就已经存在**
   不要误以为 `pmm_init` 才开启分页；它只是建立物理页管理的数据结构。

10. **`check_alloc_page()` 会临时改动空闲链表**
    测试内部会保存并恢复 `free_list` 和 `nr_free`，这是测试代码的正常行为。

## 9. 拓展：Buddy System 与 SLUB 在流程中的位置

### 9.1 Buddy System：替换 `pmm_manager`

Buddy 与 Best-Fit 实现同一组 `pmm_manager` 接口，只是算法不同：

```
init_pmm_manager()
  └─ pmm_manager = &buddy_pmm_manager
       ├─ buddy_init()           初始化各阶空闲链表
       ├─ buddy_init_memmap()    把 31930 页按 2 的幂分解
       ├─ buddy_alloc_pages()    请求向上取整到 2^k，逐级二分分裂
       └─ buddy_free_pages()     放回后与伙伴 off ^ (1<<k) 循环合并
```

关键区别：

- 块大小必须是 `2^k` 页；
- 分配 `n` 页时实际消耗 `2^ceil(log2(n))` 页；
- 伙伴关系由相对空闲区起点的偏移决定：`off ^ (1 << k)`；
- `init_memmap` 传入的 `n = 31930` 不是 2 的幂，需要贪心分解为
  `16384 + 8192 + 4096 + 1024 + 256 + ...` 等块。

当前 `init_pmm_manager()` 默认选择 Best-Fit；如需测试 Buddy，可临时切换为：

```c
pmm_manager = &buddy_pmm_manager;
```

### 9.2 SLUB：位于页分配器之上

SLUB 不替代 `pmm_manager`，而是**复用**它的页分配接口：

```
slub_init()                 初始化各 size class 的 cache
slub_malloc(size)
  ├─ 小对象 → slub_cache_alloc()
  │            ├─ 从 partial slab 的 freelist 弹对象
  │            └─ 没有 partial → alloc_pages(1) 新建 slab
  └─ 大对象 → alloc_pages(npages)，页首放 slub_slab 头
slub_free(ptr)
  ├─ 小对象 → slub_cache_free()
  │            ├─ 对象压回 freelist
  │            └─ slab 空了 → free_pages() 整页归还
  └─ 大对象 → free_pages() 整页归还
```

所以完整的层次是：

```
应用/内核模块
    │ slub_malloc / slub_free
    ▼
SLUB 对象分配器
    │ alloc_pages / free_pages
    ▼
Best-Fit / First-Fit / Buddy 页分配器
    │ Page 描述符 + free_list
    ▼
物理内存
```

当前 `kern_init()` 默认没有调用 `slub_init()` 和 `slub_check()`；报告中的 SLUB 测试是临时加入后运行的，验证完已恢复，以保证 `make grade` 仍为 20/20。

## 11. 最终记忆版

如果只记一条主线，记这个：

```
entry.S 开页表
  → kern_init
    → dtb_init                  “内存在哪？多大？”
    → pmm_init
      → init_pmm_manager        “用哪个分配器？”
      → page_init               “每页建一个 Page 描述符，划出空闲区”
        → init_memmap           “把空闲区交给分配器”
      → check_alloc_page        “分配/释放对不对？”
    → alloc_pages / free_pages  “运行时真正分配和回收”
```

如果只记 `page_init` 的五步：

```
读 DTB → 设 va_pa_offset / npage → 在 end 后放 pages 数组
      → 全部置 reserved → 从 freemem 开始 init_memmap
```

如果只记 Best-Fit 的四步：

```
遍历找最小够大块 → 摘链 → 大了就分裂 → 更新 nr_free
```

释放则是：

```
清状态 → 按地址插回 → 与前合并 → 与后合并
```
